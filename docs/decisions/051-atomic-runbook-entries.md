# ADR 051 — Atomic runbook entries

**Status:** Accepted
**Date:** 2026-10-28
**Amends:** ADR 044, ADR 049

---

## Context

The 2026-10-28 review found that learning yield was still about zero, and the noise was growing:

- **The verdict lane rewrote whole runbooks that repeated the seed.** It returned a full `DistilledRunbook` (title, when-to-use, tools, hypotheses, fix, rule, pitfalls), and `no_new_knowledge` was usually ignored.
  - The mosquitto candidate's decision rule was the seed's. It was pinned to "7.1.2 → 7.1.3", and its title was the prompt instruction itself.
  - The Sonos candidate restated `seed_device_offline` and recommended `get_netalertx_presence`, a tool that does not exist.
- **A verdict merge erased `## Procedure notes`.** `_merge_in_sqlite` replaced `approach` wholesale, so the procedural lane's notes, written seconds earlier, were lost.
- **LLM procedural lessons graded in reverse.** Grounding kept "get_pueo_command_catalog … succeeded without an error" and rejected the one real lesson (the wrong add-on slug). The deterministic extractor (#991) had already caught that failure correctly.

The root cause is that a learned runbook was one blob of text, regenerated by the LLM each time. Nothing tied a sentence to the session that produced it, and nothing in code checked it against the seed.

---

## Decision

### 1. `runbook_entries` (migration V42)

Each piece of learned knowledge is its own row:

| column | meaning |
|---|---|
| `signature` | concrete session signature |
| `kind` | `decision_rule` \| `pitfall` \| `procedure` |
| `text` | one sentence |
| `tool` | first registered tool the text names (procedure: the step's tool) |
| `episode_refs` | JSON list of supporting episodes |
| `success_count` / `failure_count` | verified support. For `procedure`: sessions it was seen in |
| `created_at` / `updated_at` / `retired_at` | lifecycle; retired rows are never rendered |

Entries are inserted or reinforced, never rewritten. A near-duplicate (same kind, ≥ 60 % token overlap; for `procedure`, exact normalised text) adds 1 to `success_count` and appends the episode, once per episode.

### 2. Verdict lane: a delta, gated in code

`_distill_verified` asks for `DistilledDelta{decision_rules[], pitfalls[], instance_facts[]}`. Each item cites an `evidence_step`. There is no title, no when-to-use and no tool list. Empty lists are the expected answer when the session confirms the seed.

Before an item is written, `_gate_item` checks, in order:

1. **Grounding**: `_fact_is_grounded` against the whole trace (calls, outputs, errors) plus the user's correction.
2. **Seed overlap**: `_overlaps(text, seed)` rejects ≥ 60 % content-token coverage. Framing words ("decisive factor", "the session treated") are ignored, so they cannot dilute the overlap.
3. **Version scrub**: an item containing `\d+.\d+(.\d+)?` is rejected when the matched seed is a wildcard, or when there is no seed.
4. **Known tools**: every tool-like name must be registered in the ha, chat or netalertx registry. A tool-like name is a snake_case word followed by `(`, or one starting with a verb a registered tool starts with. Slugs (`core_mosquitto`) and dotted entity ids pass.

Each dropped item is logged as `distillation_entry_rejected reason=…`, and each kept one as `distillation_entry_written action=inserted|reinforced|unchanged`. Instance facts are unchanged: per-step grounding, stored in `agent_memory`.

A **failure** verification with a correction first adds 1 to `failure_count` on the live `decision_rule`/`pitfall` entries created at or before the session's `session_outcomes.created_at`, because those are the entries its pre-injected runbook showed. An entry is retired once `failure_count ≥ success_count + 1`.

### 3. Procedural lane: deterministic only

`distill_procedure` keeps `extract_procedure_facts` and `_record_tool_quirks`, and writes the notes as `procedure` entries. The LLM prompt, `ProceduralLessons`, `_lesson_is_grounded` and `_grounded_lessons` are removed, and the lane no longer takes a model or LLM client.

### 4. Rendering

`render_learned_runbook(db_path, signature, store)` rebuilds the signature's candidate/validated `agent_strategies` row from its live entries:
- title: `Learned: <signature>`
- sections, best-supported first, empty ones omitted: `## Decision rules`, `## Pitfalls`, `## Procedure notes` (last, capped at 8)
- episode refs: the union of the entries' refs

The row keeps its state (a validated row stays validated). It is synced to Chroma with `sync_strategy_to_chroma`, which now carries `signature` metadata, so family scoping keeps working. When no live entries remain, the row is set to `discarded` and removed from Chroma.

`_fetch_signature_chunks`, `kb_contributor` and `/runbooks` still read `approach`. A procedure-only runbook emits just the `[PROCEDURE NOTES]` chunk, with no empty body chunk. `_auto_validate_if_eligible` is unchanged and stays signature-level through `runbook_usage`. The learning-health table gains an **Entries** column (live, with retired in brackets).

---

## Consequences

- **A verdict write can no longer erase procedure notes**: both lanes add rows, and the render combines them.
- **The seed stays the source of truth for verdicts**: a learned runbook holds only what the seed lacks, and each line traces to its sessions.
- **Wrong entries age out**: corrections count against the entries a session saw, so bad rules retire instead of being re-rendered forever.
- **Legacy candidates**: their whole-runbook text is replaced on the first render for that signature. The four live legacy candidates and the stale agent_memory fact are deleted manually (runbook yield v3 S6).
- **Stricter output**: grounding on the whole trace is strict on paraphrase, so the model must reuse the trace's words. The prompt says so, and replaying the mosquitto and Sonos sessions kept the novel lessons.
- **Rollback**: revert the commit. V42 is additive, so the table is simply unused, and rendered `approach` text stays readable by the old code.
